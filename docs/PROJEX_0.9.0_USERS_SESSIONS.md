# PROJEX 0.9.0-preview.1 — Users & Sessions

**حالة التحقق:** كُتب بدون .NET SDK أو PostgreSQL ولم يُبنَ ولم يُشغَّل. المتطلبات: FR-AUTH-002/003/006، FR-IAM-001/005/006.

## الجلسات
- `POST /api/v1/auth/login` يعيد الآن `refreshToken` ويُنشئ جلسة (`identity.user_sessions`, migration 010). صلاحية access token صارت **15 دقيقة** (كانت 30).
- `POST /api/v1/auth/refresh` `{tenantKey, refreshToken}`: يدوّر الـ refresh token في كل استخدام. إعادة استخدام توكن قديم تُلغي الجلسة وتُسجَّل في التدقيق (`auth.refresh.reuse_detected`).
- `POST /api/v1/auth/logout`: يلغي الجلسة الحالية.
- الـ refresh token يُخزَّن كـ SHA-256 فقط. عمر الجلسة 14 يومًا منزلقًا وبحد أقصى 30 يومًا.
- كل طلب يتحقق أن جلسة التوكن ما زالت فعّالة (استعلام واحد لكل طلب)، فيسري الخروج وتعطيل المستخدم **فورًا**. التوكنات القديمة بلا `session_id` تُرفض: يلزم تسجيل دخول جديد بعد الترقية.

## إدارة المستخدمين (CompanyAdmin فقط)
- `GET /api/v1/identity/users` — القائمة، آخر دخول، القفل، الشركات.
- `POST /api/v1/identity/users` `{email, password, companyId}` — إنشاء مستخدم بلا أدوار؛ الأدوار على المشاريع عبر `/projects/{id}/members`.
- `POST .../{id}/disable | enable | unlock` — التعطيل يلغي كل جلسات المستخدم؛ لا يمكن تعطيل نفسك ولا آخر مدير فعّال.
- لا حذف للمستخدمين (FR-IAM-005).

## غير منفَّذ بعد
- MFA، تغيير/إعادة تعيين كلمة المرور، دعوة بالبريد، سياسات قفل قابلة للضبط لكل مستأجر، إدارة الأجهزة الموثوقة، صفحة الجلسات للمستخدم.
- تنظيف الجلسات المنتهية دوريًا (Background job).
- الاستعلام لكل طلب قد يحتاج تخزينًا مؤقتًا قصيرًا (Redis) عند الحمل العالي.
